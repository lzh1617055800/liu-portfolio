C++ 轻量级 HTTP 服务器

用 epoll + Reactor + 工作线程池，把一个能处理真实请求的服务端骨架搭出来。

核心链路

ET 模式事件循环 → 连接分发 → 线程池处理 → HTTP/1.1 响应

我验证了什么

Keep-Alive、GET/POST、MIME 静态文件、15s 空闲连接清理，以及 285 allocs / 285 frees 的内存检查。

我做了什么

把 socket 接入、事件循环、请求解析、响应发送和连接回收拆成独立职责，便于定位阻塞、断连和资源释放问题。

关键取舍

用 ET + 非阻塞 IO 减少无效唤醒，用 Reactor 分发事件，再交给工作线程池处理业务，避免主循环承担耗时逻辑。

验证结果

用 curl 覆盖 GET / POST、静态文件和 Keep-Alive 场景，并用 Valgrind Memcheck 检查到 285 次分配与释放闭合。

LightMark 跨平台 Markdown 编辑器

不是再做一个文本框，而是处理编辑器真正会遇到的性能和状态问题。

核心链路

QTextDocument → 差分更新 → 局部渲染 → 预览与光标状态保持

我解决的问题

虚拟化编辑、200ms 预览刷新、30s 自动保存、编码识别，以及基于 SSE 的 AI 对话流。

我做了什么

围绕编辑、预览、文件和对话四条链路组织模块，处理光标状态、局部更新、保存时机和流式响应的衔接。

关键取舍

不每次重建整页预览，而是用差分更新和 200ms 定时刷新平衡输入响应与渲染压力；自动保存独立为 30s 周期。

验证结果

支持 Windows / Linux 构建，兼容 UTF-8、UTF-16、GBK，并通过 QNetworkAccessManager 接收 SSE 对话流。
